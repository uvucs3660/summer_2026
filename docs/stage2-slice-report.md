## Part 1 — API contract verification

**Endpoint (verified live, not assumed from docs):**

```
POST https://api.elevenlabs.io/v1/text-to-speech/{voice_id}/with-timestamps
```

This is the non-streaming timestamped-synthesis endpoint. `GET /v1/text-to-speech/{id}/with-timestamps`
does not exist; the streaming sibling `/stream/with-timestamps` was not used since this pipeline needs
one full response per deck, not a stream.

**Response shape (verified against two live calls, an 81-character probe on `eleven_multilingual_v2`
and the same probe on `eleven_v3`):**

```jsonc
{
  "audio_base64": "<base64 mp3>",
  "alignment": {
    "characters": ["T", "h", "i", "s", " ", ...],                 // 1:1 with the input text
    "character_start_times_seconds": [0.0, 0.081, 0.139, ...],
    "character_end_times_seconds":   [0.081, 0.139, 0.186, ...]
  },
  "normalized_alignment": {
    "characters": [...],                // NOT 1:1 with input — 83 entries vs 81 sent in the
    "character_start_times_seconds": [...],  // probe; re-tokenized/shifted, unsuitable for
    "character_end_times_seconds": [...]     // offset mapping
  },
  "quality_check": null
}
```

`alignment` (not `normalized_alignment`) is what stays index-aligned with the exact text sent — that's
what slide-offset mapping requires, and what this module uses.

**Model chosen: `eleven_multilingual_v2`, not the spec's placeholder `eleven_v3`.**

Both models return 200 and valid alignment data on `/with-timestamps` for a short probe — so `eleven_v3`
*does* support the endpoint, which the spec flagged as unverified. But `GET /v1/models` reports:

| model_id | max_characters_request (subscribed) |
|---|---|
| `eleven_v3` | **5,000** |
| `eleven_v3_conversational` | 5,000 |
| `eleven_multilingual_v2` | **10,000** |
| `eleven_flash_v2_5` / `eleven_turbo_v2_5` | 40,000 |
| `eleven_turbo_v2` / `eleven_flash_v2` | 30,000 |

The concatenated `w03-ai-skills` script is 8,666 characters — over `eleven_v3`'s 5,000-character cap,
so it cannot serve the deck in the one synthesis call the design requires without chunking (which would
break the single-timeline alignment this design depends on). `eleven_multilingual_v2` fits (8,666 <
10,000), is the endpoint's own documented default, and is the model line built for stable long-form
narration — the right tradeoff for an 11-minute single-voice lecture over the alpha, shorter-context,
more-expressive `v3` line. **Decision: `eleven_multilingual_v2` for all stage ② synthesis until decks
routinely exceed ~9.5k characters, at which point chunking would need its own design.**

## Part 4 — Player

`content/cs3540/2026/lectures/slides/_lectures/player.html`, generated by
`~/code/fivex/mod_node/modules/lecture/build-player.ts`.

- **The lecture JSON is inlined** into the HTML as a `<script type="application/json">` block at build
  time, not fetched at runtime. Opening the file via `file://` (Chrome/Safari's local-file rules) blocks
  `fetch()` of a sibling JSON file with no CORS headers, so inlining was necessary, not optional — this
  was confirmed during testing (see below), not assumed.
- The mp3 is *not* inlined (8.8 MB) — the `<audio>` tag loads a local mp3 directly over `file://`
  without the fetch restriction, so `player.html` and `w03-ai-skills.mp3` must stay siblings in the same
  directory (they do).
- Renders: visible slide counter (`"4 / 10"`), current slide heading + blocks (bullets → `<ul>`, code →
  `<pre><code>`, para/quote → text, image → `<img>` with a graceful `[image: <src>]` fallback if the
  diagram file isn't reachable), the current slide's full script text for read-along/mispronunciation
  checking, and a clickable slide list that seeks the audio and jumps.
- **Bug found and fixed during verification:** the first version's click-to-jump set
  `audio.currentTime` before the browser had loaded audio metadata, which Chromium/WebKit silently
  drop (no seek, no error) — so clicking a slide changed the visible slide but the audio kept playing
  from wherever it already was. Fixed by adding `preload="auto"` and gating the seek on
  `audio.readyState >= 1` (`HAVE_METADATA`), waiting on a one-shot `loadedmetadata` listener otherwise.
  Verified via a real Chromium session (Playwright) against a Range-request-capable local server (not
  Python's `http.server`, which silently ignores `Range` headers and would have made this bug
  invisible in testing): after the fix, `jumpToSlide(3)` correctly lands the audio position within the
  target slide's span and the timeupdate-driven auto-advance correctly switches slides mid-playback.

## Surprises / things worth flagging forward

1. **`eleven_v3` technically works on `/with-timestamps`, but its 5,000-character request cap makes it
   unusable for any full deck over that size** — `w03-ai-skills` alone (8,666 chars) already exceeds it,
   and it's one of the shorter decks in the corpus. If `v3`'s prosody is ever wanted, stage ② would need
   a chunking design (and a way to keep timestamps contiguous across chunk boundaries), which is out of
   scope for this slice.
2. **`normalized_alignment` is not usable for offset mapping** — it re-tokenizes and is not 1:1 with the
   input string (83 characters back for an 81-character probe). This isn't documented anywhere obvious;
   it was only visible by diffing array lengths against the sent text. Anyone reaching for the
   "normalized" field because it sounds more correct will get silently wrong offsets.
3. **Python's `http.server` ignores `Range` headers and returns 200 instead of 206.** This makes
   `<audio>` seeking fail silently under it, which would have hidden the click-to-jump bug above during
   local testing had a real Range-aware server not been used to verify. Worth remembering for any future
   local player testing — a plain `python3 -m http.server` is *not* a faithful stand-in for `file://` or
   a production static file server when audio seeking is involved.
4. **ElevenLabs' billed character-count delta (8,845) didn't exactly match characters sent (8,828)** —
   a small, unexplained 17-character gap. Immaterial at this scale, but worth knowing the account meter
   and "characters sent" aren't perfectly identical accounting if this is ever audited closely at 32k-word
   full-course scale.
