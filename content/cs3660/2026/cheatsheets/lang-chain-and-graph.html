The Forest of Language
A field guide to LangChain & LangGraph

Two ways to move an idea through the woods: let it ride the stream — a fixed, one-way flow — or send a hiker down the trails, where paths fork, loop back, and the backpack fills up along the way.

🌲 Forest — the big picture 🌳 Trees — each concept, up close 🍃 Leaves — the code, vein by vein
🌲 Forest level · the view from the canopy

Two tools, one ecosystem

Climb above the treetops for a moment. Below you is the whole landscape of building applications with large language models, and two ways of moving through it.

LangChain is a framework for composing LLM applications out of reusable parts — prompts, models, output parsers, retrievers — snapped together into a pipeline. In our forest, LangChain is the stream: water enters at the spring, flows over a fixed sequence of stones, and comes out the other end transformed. It always flows downhill, one way. Predictable, fast to build, easy to reason about.

LangGraph is a lower-level library (from the same team) for building stateful, agentic workflows as a graph: nodes connected by edges, where the path can branch based on decisions, loop back on itself, pause for a human, and remember everything in a shared state. In our forest, LangGraph is the trail network: a hiker sets out from the trailhead carrying a backpack (the state). At every clearing (node) something happens to the backpack. At every fork (conditional edge) a signpost decides where to go next — including back the way they came.

One more canopy-level fact before we descend: these libraries share DNA. LangGraph is built by the LangChain team and speaks the same Runnable language — a compiled graph is a Runnable, so you can .invoke() it, stream it, and even pipe it like any chain. Learn the stream first; the trails will feel familiar.

🌲 Forest level · why the stream exists

💧 The Stream — LangChain

Calling an LLM raw is like scooping water straight from the spring: it works, but every app ends up rewriting the same plumbing — formatting the prompt, calling the model, cleaning up the response. LangChain turns that plumbing into stones you place once and let the water run over forever.

🌳 Tree level · the four trees on the bank

Meet the species

Every classic chain is built from a handful of components. Each one is a Runnable — LangChain's universal interface: anything with .invoke(), .stream(), and .batch(). Because they all share this interface, they snap together with the pipe operator |. The growth ring on each card shows the order the water reaches it.

1

Prompt Template

Populus formatus — the shaping poplar

Holds your prompt text with {variables} as gaps. When water (a dict of inputs) arrives, the gaps fill in and out flows a list of structured messages ready for the model.

2

Chat Model

Quercus sapiens — the thinking oak

The LLM itself — ChatAnthropic, ChatOpenAI, and dozens more behind one identical interface. Takes messages in, returns an AIMessage out. Swap providers by changing one line.

3

Output Parser

Salix extractus — the sifting willow

Model replies arrive wrapped in metadata. Parsers strain out what you want: StrOutputParser yields plain text; others produce JSON, lists, or Pydantic objects.

|

LCEL — the current itself

Fluvius expressus — the expression river

The LangChain Expression Language. The pipe | connects Runnables so each one's output pours into the next one's input. The whole chain becomes a single Runnable — streamable, batchable, composable.

🍃 Leaf level · the code, vein by vein
The exact chain you just ran, in Python 
# pip install langchain langchain-anthropic
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_anthropic import ChatAnthropic

# Stone 1 — the shaping poplar: text with gaps
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a cheerful forest ranger who loves trivia."),
    ("human",  "Tell me one fun fact about {topic}."),
])

# Stone 2 — the thinking oak
model = ChatAnthropic(model="claude-sonnet-4-5")

# Stone 3 — the sifting willow
parser = StrOutputParser()

# The current: pipe them together. The chain is itself a Runnable.
chain = prompt | model | parser

result = chain.invoke({"topic": "owls"})
print(result)   # → "Owls can rotate their heads about 270 degrees…"
Three superpowers you get for free from LCEL 
# 1. Streaming — tokens flow out like water, as they're generated
for chunk in chain.stream({"topic": "moss"}):
    print(chunk, end="", flush=True)

# 2. Batching — run many inputs through the same stream in parallel
chain.batch([{"topic": "ferns"}, {"topic": "foxes"}, {"topic": "lichen"}])

# 3. Composition — chains nest inside chains like tributaries
title_chain   = title_prompt | model | parser
poem_chain    = ({"title": title_chain} | poem_prompt | model | parser)
poem_chain.invoke({"topic": "a river at dawn"})

The stream's one law: water flows downhill. A chain cannot decide mid-flow to skip a stone, revisit an earlier one, or wait at a pool until a condition is met. The moment your app needs to choose, retry, or remember — you need trails. Lace up.

🌲 Forest level · why the trails exist

🥾 The Trails — LangGraph

Real agents don't flow — they hike. They look around, pick a direction, gather what they need, double back when they must, and remember every step. LangGraph gives you a map-maker's kit: define the clearings, blaze the trails between them, post signs at the forks, and hand your hiker a backpack.

🌳 Tree level · the five trees along the trail

Meet the species

1

State — the backpack 🎒

Sacca communis — the shared pack

One typed dictionary that every node can read and write. It's the only way nodes communicate — the hiker carries it to every clearing. Each field can declare a reducer that says how updates merge in: overwrite the old value, or append to it.

2

Nodes — the clearings ⛺

Statio operis — the working glade

Plain Python functions. Each receives the current state and returns a partial update — just the fields it changed. A node might call an LLM, run a tool, or crunch data. LangGraph merges the update into the backpack.

3

Edges — the blazed trails 🪧

Semita fixa & semita optionis

Plain edges always lead to the same next clearing. Conditional edges are forks with a signpost: a routing function reads the backpack and returns the name of the next node. START is the trailhead; END is the summit.

4

Cycles — the loop trail 🔄

Circuitus utilis — the useful circuit

Trails may lead back to earlier clearings — the thing streams can never do. This is the heartbeat of every agent: think → act → observe → think again, looping until the signpost finally points to the summit.

5

Checkpointers — the campsites 🔥

Castra memoriae — the camps of memory

A checkpointer snapshots the backpack after every step, keyed by a thread_id. Resume a hike days later, rewind to any campsite ("time travel"), or pause at one and wait for a human to approve the next leg.

      The exact graph you just hiked, in Python
      


# pip install langgraph
from typing import Annotated
from typing_extensions import TypedDict
import operator
from langgraph.graph import StateGraph, START, END

# ── 1. The backpack: typed state, with reducers per field ──────────
class TrailState(TypedDict):
    goal: str                                     # overwrite (default)
    supplies: Annotated[list[str], operator.add]  # reducer: append!
    steps: int

NEEDED = ["water", "map", "rope"]

# ── 2. The clearings: functions of state → partial update ──────────
def ranger(state: TrailState):
    # In a real agent this is an LLM call deciding what to do next.
    return {"steps": state["steps"] + 1}

def gather(state: TrailState):
    nxt = NEEDED[len(state["supplies"])]
    return {"supplies": [nxt]}   # reducer APPENDS this to the list

# ── 3. The signpost: reads the pack, names the next clearing ───────
def signpost(state: TrailState):
    return "gather" if len(state["supplies"]) < 3 else END

# ── 4. Blaze the trails ─────────────────────────────────────────────
trail = StateGraph(TrailState)
trail.add_node("ranger", ranger)
trail.add_node("gather", gather)
trail.add_edge(START, "ranger")
trail.add_conditional_edges("ranger", signpost)   # the fork
trail.add_edge("gather", "ranger")               # the loop back

app = trail.compile()   # the compiled graph is a Runnable, like any chain
app.invoke({"goal": "reach the summit", "supplies": [], "steps": 0})
# → {'goal': 'reach the summit', 'supplies': ['water','map','rope'], 'steps': 4}

      

    


    

      Campsites: adding memory with a checkpointer
      


from langgraph.checkpoint.memory import MemorySaver

app = trail.compile(checkpointer=MemorySaver())

# Every invocation with the same thread_id resumes from the last campsite
config = {"configurable": {"thread_id": "hike-42"}}
app.invoke({"goal": "summit", "supplies": [], "steps": 0}, config)

# Days later — the backpack is exactly where the hiker left it:
app.get_state(config).values
# Swap MemorySaver for SqliteSaver / PostgresSaver in production.

📓 Field Notes — what to remember

    

      
💧 LangChain in one breath

        
Composable pieces + the pipe. prompt | model | parser. One direction, no memory, wonderfully predictable. Reach for it when the path never forks.

      
🥾 LangGraph in one breath

        
State + nodes + edges. Nodes return partial updates; reducers merge them; conditional edges route; cycles make agents; checkpointers make memory.

      
🎒 The one golden rule

        
In LangGraph, everything travels in the backpack. If two nodes need to share something, it goes in the state — there is no other trail between them.
